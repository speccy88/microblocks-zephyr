# P4 inline results in the staged JavaScript editor

The P4 package uses the existing identified connection and native RPC208/209
protocol. Supported image-producing and PCM-recording expressions show a
transient result under the producing block. Expand/collapse uses that block's
Morphic hierarchy; the services panel offers matching accessible controls.
Playback is explicit. The editor requests snapshots only from results of code
the user runs; the preview client never starts a camera or microphone.

A run negotiates a fresh29-bit native media session before recompilation. Code
adds `p4:mediaSnapshot` after the original handle expression; hidden library
bodies stay unchanged. The primitive preserves the original handle. Readback
validates and removes generated wrappers, preferring the P4 namespace over its
generic IO alias. Session and site numbers never become block inputs or source.
If media capabilities are unavailable, normal program execution continues
without preview instrumentation.

Results expire on rerun, Stop, project replacement, deletion and disconnect.
Late session/token/request replies are rejected. Images fit160x90, with their
aspect ratio retained at the block's zoom. Native reads are at most512 bytes;
the browser retains at most eight results, two audio clips and1MiB of accounted
media. Disposal pauses audio, revokes Blob URLs and clears canvas storage.
Copies and restored deleted blocks receive fresh site identities and no media.
Explicit collapse survives subsequent results on the same block.

The test entry in `tests/support/js_p4_media_graphical.js` is inserted only into
a separate local fixture page. Product builds contain no stored pixels, PCM or
fixture buttons. Twelve focused cases exercise the actual pinned compiler,
decompiler, code manager and morphs plus protocol-faithful RPC fixtures. The
graphical check displays synthetic RGB bars and generated silent PCM; it tests
drag, zoom, collapse, explicit Play/Pause, expiry and source reopening. See
[the dated receipt](../evidence/2026-10-28/js-p4-media/README.md).

These checks do not establish physical camera, microphone, speaker, USB, WSS or
inference behavior. The P4 owner's checkout and COM5/COM12 remain untouched.
GP, the upstream JS source pin, the native firmware, paused SFC and the live
website remain unchanged. Broader combinations of embedded library metadata
and board readback still need acceptance with the reconciled owner firmware.
