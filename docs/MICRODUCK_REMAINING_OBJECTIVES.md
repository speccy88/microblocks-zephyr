# MicroDuck remaining brief objectives

This separates missing software from acceptance gates. The update-watch merge
and read-only preflight are retained on the isolated integration branch. The
additive camera checkpoints implement a receive-only signaling/browser peer
core, video-element frame observer and fictional viewer lab with internal
fakes. They open no live camera, signaling endpoint or robot connection.
The physical robot has not arrived.

The isolated [JS typed-library migration](JS_TYPED_LIBRARIES.md) now imports
the six normal gateway modules through the actual pinned editor implementation
and executes representative compiled wrappers on the real Pi. Depth/gamepad
sources remain fictional; graphical and physical acceptance are still pending.

The [four-service matrix](MICRODUCK_SERVICE_CAPABILITIES.md) makes the requested
robotd/mediad/tofd/padd block coverage explicit. Separate simulated depth-zone,
raw-axis and button JSON blocks now consume bounded source-shaped Unix streams;
coherent snapshots and native numeric/state helpers are now implemented and
tested on the real Pi with fake services. Live commissioning, continuous freshness
and physical input remain gaps. These differ from health/configuration reporters.
The explicit robot methods, requested telemetry and robotctl diagnostics are
tracked in [the source-backed API mapping](MICRODUCK_ROBOT_API.md).
