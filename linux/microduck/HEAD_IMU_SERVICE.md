# Read-only tofd adapter through the normal gateway

Spec-first continuation after ae86fcd. The finite checked tofd reader and typed
decoder exist, but the normal Gateway rejects their simulation-only names.
Close that connection with explicit read-only local adapter methods and a
separate MicroBlocks library. Keep existing simulation methods/markers and all
existing primitive indices intact. Do not add motion or arbitrary forwarding.
The adapter requires Python3.11+ and this linux/microduck source directory beside
the native VM. A standalone gateway/service installer is still a deployment gap.

The normal gateway optionally loads a separate private, bounded, same-user config
file containing exactly version1, daemon:"tofd", an absolute socket path and an
expected numeric UID. No discovery, guessed path/owner, fallback, permission edit
or endpoint input from blocks. The UID/path checks describe transport consistency,
not trusted daemon identity or physical hardware. Shipping configuration requires
actual inventory; no shipping config is generated by this checkpoint.

Local microduck.headImu.capture/read/release use the already reviewed
head_imu.stream first-request protocol (no hello), strict field shapes, finite
deadline and four five-second snapshots. Reuse unit conversion/expiry logic with
an explicit envelope factory. A normal service result has origin local_ipc,
source tofd, physical_hardware_verified:false and physical_movement_enabled:false;
it has no simulation member because the transport cannot establish data origin.
A fake service produces local_ipc too: this describes only the adapter path.

Append headImuReading to native set22. It accepts only this adapter envelope;
headImuSample continues to require the simulation envelope. Neither decoder
accepts the other's records. Missing/unusable/error values stay unextractable,
64-bit clocks remain exact, and GC safety/resource bounds remain unchanged.
Capabilities report whether this adapter is configured and its read-only limits.
Gateway stop closes pending reads and releases retained snapshots; no replay.

Package Head_IMU.ubl and a read-only example only for MicroDuck, beside the
separate simulation library. Document how to start the standard gateway and VM
without changing services, network or security settings. No listener except the
existing private Unix gateway; no installation, live daemon probe, reboot or
physical movement. Pi acceptance uses an independently configured normal gateway
and protocol-faithful fake tofd, with its simulated input explicitly recorded.

Acceptance: private config schema/permissions and no auto-inference; source-shaped
Unix protocol and UID-before-write; normal gateway routes/capabilities/disabled
semantics; native blocks/typed origins/GC; cancellation/expiry/bounds/errors;
editor-facing library/example packaging; full local validator and selected real
Pi ordinary/sanitizer suites. Physical/beta/live shipping and graphical acceptance
remain open. Existing Edge/numeric-suite denials are not retried.

## Try the normal path with simulated input

Start this Linux lab in a fresh directory; it writes its own private configs
and starts a fictional tofd plus the normal gateway:

```sh
python3 linux/microduck/head_imu_gateway_fixture.py --directory /tmp/head-gateway-NEW
```

The printed JSON explicitly says simulation:true and names the normal gateway
socket. Run the current SmallVM with its existing --microduck-socket option set
to that path and its usual private program directory. Import MicroDuck and
Head_IMU, then open head-imu.ubp. The MicroDuck editor package includes both.
Capture, check the status with reading-known, read the desired scalar/vector
components, then release. All records are [status,value,unit,origin]; only ok has
an extractable value. This fixture's data is simulated even though origin says
local_ipc: that origin describes the configured Unix adapter, not the sensor.
Stop the lab with Ctrl-C; owned sockets and pending subscriptions close while
private configs/metadata remain for inspection. No network listeners or service
settings are involved. Use a new directory on the next run.

## Configure a source after inventory

The standard gateway accepts its existing private version1/upstreams config;
upstreams may be empty when this read-only adapter is configured. Supply a
separate private head config with these exact members:

| Member | Required value |
|---|---|
| version | Integer1 |
| daemon | String tofd; no robotd/beta fallback |
| path | Absolute canonical socket path established by inventory |
| uid | Expected numeric server UID established by inventory |

Start a foreground gateway in an already private project directory:

```sh
python3 linux/microduck/gateway.py --config /absolute/private/gateway.json --head-imu-config /absolute/private/head.json --socket /absolute/private/gateway.sock
```

No shipping values are supplied or guessed here. Config files must be private,
regular and owned by the current user; symlinks/unknown members are refused.
The source socket owner, parent permissions, inode and SO_PEERCRED are checked
before sending. This is still not daemon attestation, calibrated data, freshness
or permission to move. Missing adapter config yields an explicit error. The
gateway capabilities report adapter configuration and read-only limits.
SmallVM talks directly to this gateway. The separate Python convenience client's
legacy allowlist has not gained these adapter names in this checkpoint; use the
native blocks/fixture path described above.

Protocol/units remain those in [the pinned source audit](tests/head-imu-source.json)
and [head IMU specification](HEAD_IMU_SIMULATION.md). Beta frame mapping and actual
shipping identity/permissions remain acceptance gates; no system setting is changed.
