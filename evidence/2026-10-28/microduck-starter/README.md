# MicroDuck starter layers, local simulation checkpoint

The optional Starter Lab imports ten modules and178 functions through the
actual pinned JS file/import path. The six normal modules/140 functions remain
unchanged. Separate Simple Sensors and Simple Practice categories coexist with
the advanced read-only and simulation categories in one project. Exact source
receipts accompany the optional bundle. Representative simple/advanced scripts
save and reopen with identical source and distinct function IDs. All functions
are within the stock1000-byte limit; the observed maximum is400 bytes.

The actual verified local SmallVM executes the JS-compiled function bytes over
its official PTY/CRC protocol. Protocol-faithful private robotd/tofd/padd fixtures
provide known battery0, head temperature23125mC, depth1000mm, no_target and an
explicit observed gamepad release(false). Normal completion leaves each adapter
snapshot store empty. Missing configuration and invalid input remain errors.
Like the advanced libraries, interruption can leave a snapshot until its bounded
five-second expiry; ordinary completion is the release guarantee tested here.

Simple and advanced mock action blocks run in the same VM/interface. Confirmed
forward and yaw produce the expected scaled recorded twist; cancel clears the
mock lease. Stop/chirp/skill and advanced stop record four packets with
recorded_not_executed and physical_movement_enabled:false. False confirmation,
out-of-bounds speed, unadvertised skill and disabled backend opt-in are refused;
no additional preview is recorded. No real robot command is sent.

`native-focused-pass.log` and its receipt precede the final additional sensor
success checks. Final acceptance is the companion **504-test combined full
run**, no skips, which includes those success paths and all other tests:
[full receipt](../js-p4-media/combined-final-receipt.json),
[full output](../js-p4-media/combined-final-full.log).

The first native focused attempt failed because the fixture expected JSON for
an unadvertised skill. The native safety gate correctly returned VM error32
before forwarding. The final fixture requires that error and verifies unchanged
audit size; no gate was weakened. The original receipt was copied from a full
runner template and incorrectly labels its mode Full unchanged validator. Its
original bytes are retained as first-native-focused-receipt-original.json;
it was a focused two-test run, not a full validation. The later focused receipt
has the correct scope. The first Windows harness used an asynchronous test class
for a synchronous import check and stalled after the native skip; it was stopped
and split into a normal import class and Linux-only async native class. The
Windows import pass and one expected native skip are recorded separately.

The actual IAB editor loaded all ten categories with its target connection
still disabled. A simple timed action, advanced lease block and simple battery
reporter coexist visibly; defaults show confirmation off. Screenshots are
included; console warnings/errors are empty. The temporary server/tab is closed.
This graphical check edits offline blocks and does not execute them on hardware.
