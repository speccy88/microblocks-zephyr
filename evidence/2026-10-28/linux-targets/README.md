# Independent Linux target selection

The existing portal catalog now distinguishes standalone Raspberry Pi 5 and
**MicroDuck Rockchip RK3566 (experimental placeholder)**. The latter permits
offline preparation, while install/service/endpoint controls and its generated
editor's USB/WebSocket entry points are disabled. Generic future ARM64 releases
cannot accidentally unlock its installer. Pi remains independent of robot APIs.

The two browser screenshots show the actual local portal panels. The focused
Node log exercises both install policy and actual adapter connection guards.
The seven-profile package is built from the unchanged verified GP source pin;
this does not complete the separate seven-profile JavaScript editor migration.
Final documentation destinations use the published migration branch rather
than files not yet on main. The link-only correction has focused test evidence;
the browser preview interruption is recorded in `graphical-receipt.json`.

`pi-readonly-inventory.json` records an actual successful SSH identity/binary
check. It did not start or stop a VM or access robot services. Previous physical
Pi core, persistent program and GP reconnect evidence remains separately dated.
This slice does not claim a new native build, OS reboot, real user-service
startup, MicroDuck hardware validation or published ARM64 binary release.

See `docs/RASPBERRY_PI_5_STANDALONE.md` for normal install/launch/resume status
and its remaining acceptance gates. Main, the GP branch, the protected P4 owner
checkout, paused SFC, existing services and security settings remain untouched.
